## 二、新发现问题

### 🟠 问题 R-1：PromptBuilder 在数据库未初始化时崩溃

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟠 中等 |
| **问题类型** | 运行时健壮性 / 异常处理 |
| **所在文件** | [services/prompt_builder.py](file:///d:/Desktop/MISS/miss-backend/services/prompt_builder.py#L30-L32) |
| **影响范围** | 任何未先调用 `init_db()` 就使用 `PromptBuilder.build()` 的场景 |

**复现步骤**：
```python
from services.prompt_builder import PromptBuilder
from services.attribute_engine import MISSProfile
# 注意：没有调用 init_db()
builder = PromptBuilder()
builder.build('test', 'hello', MISSProfile())
# → sqlalchemy.exc.OperationalError: no such table: messages
```

**根因分析**：
`PromptBuilder.build()` → `ConversationStore.get_window()` → 直接查询 `messages` 表。数据库表不存在时，SQLAlchemy 抛出 `OperationalError`，`ConversationStore` 中没有任何 try/except 保护，异常直接向上传播导致 `PromptBuilder.build()` 崩溃。

**为什么现有测试没发现**：
现有测试 (`test_prompt_builder.py`, `acceptance_task2_2.py`) 都在 fixture 中先调用了 `Base.metadata.create_all()`，创建了表后才测试。而 `main.py` 中 `/health` 端点不需要数据库。这两条路径掩盖了问题。

**修复建议**：
1. **立即**（推荐）：在 `PromptBuilder.__init__()` 或 `build()` 中确保表存在
   ```python
   def build(self, session_id, user_message, profile):
       try:
           conversation_window = self._conversation_store.get_window(...)
       except OperationalError:
           conversation_window = []  # 降级：无历史窗口
   ```
2. **根本**（长期）：将 `init_db()` 从 `main.py` 模块级调用改为 FastAPI 生命周期事件
   ```python
   @app.on_event("startup")
   async def startup():
       init_db()
   ```

### 🟡 问题 R-2：config.py 中 `load_dotenv()` + `os.getenv()` 与 `BaseSettings` 功能重叠

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟡 轻微 |
| **问题类型** | 代码冗余 / 配置管理 |
| **所在文件** | [config.py](file:///d:/Desktop/MISS/miss-backend/config.py#L1-L18) |

**问题描述**：
```python
load_dotenv()                                     # ← 手动加载 .env
class Settings(BaseSettings):
    openai_api_key: str = os.getenv("OPENAI_API_KEY", "")  # ← 手动读环境变量
```

`pydantic_settings.BaseSettings` **原生支持 `.env` 文件加载和环境变量读取**。当前的写法：
- `load_dotenv()` — 冗余（BaseSettings 已经在内部调用）
- `os.getenv()` — 冗余且 eval 时机在类定义时而非实例化时

**修复方案**：
```python
class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env")
    openai_api_key: str = ""
    db_url: str = "sqlite:///./miss.db"
    vector_db_path: str = "./vector_db"
    ...
```
或者至少去掉 `load_dotenv()` 和 `os.getenv()`，直接用字段默认值。

### 🟡 问题 R-3：database.py 中 `check_same_thread=False` 硬编码

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟡 轻微 |
| **问题类型** | 数据库可移植性 |
| **所在文件** | [database.py](file:///d:/Desktop/MISS/miss-backend/database.py#L6) |

**问题描述**：
```python
engine = create_engine(config.db_url, connect_args={"check_same_thread": False})
```

`check_same_thread` 是 **SQLite 专有参数**。当 `DB_URL` 切换为 PostgreSQL / MySQL 时，这个参数不会被使用（psycopg2 等驱动会忽略），不会直接报错，但属于"意外传入的参数"。

**修复方案**：
```python
import re
extra = {}
if "sqlite" in config.db_url:
    extra["connect_args"] = {"check_same_thread": False}
engine = create_engine(config.db_url, **extra)
```

### 🔵 问题 R-4：main.py 中 `init_db()` 在模块导入时执行

| 项目 | 内容 |
|------|------|
| **严重程度** | 🔵 建议 |
| **问题类型** | 应用生命周期 |
| **所在文件** | [main.py](file:///d:/Desktop/MISS/miss-backend/main.py#L5-L7) |

**问题描述**：
```python
from database import init_db
init_db()      # ← 模块级调用，导入时立即执行
app = FastAPI(...)
```

`init_db()` 在 `main` 模块被导入时立即执行。如果数据库不可用，整个应用（包括 `/health` 端点）都无法启动。

**修复方案**：
```python
app = FastAPI(...)

@app.on_event("startup")
async def startup():
    init_db()
```

### 🔵 问题 R-5：ConversationStore 数据库操作缺少异常处理

| 项目 | 内容 |
|------|------|
| **严重程度** | 🔵 建议 |
| **问题类型** | 异常处理 |
| **所在文件** | [services/memory_manager.py](file:///d:/Desktop/MISS/miss-backend/services/memory_manager.py#L6-L34) |

**问题描述**：
`add_message()` 和 `get_window()` 都没有 try/except 保护。任何数据库异常（表不存在、磁盘满、连接断开）都会直接传播到调用方。

**当前代码**：
```python
def add_message(self, session_id, role, content):
    db = SessionLocal()
    try:
        msg = MessageModel(...)
        db.add(msg)
        db.commit()
    finally:
        db.close()          # ← finally 里只有 close，没有 rollback
```

如果 `db.commit()` 抛异常，事务不会回滚，数据库可能处于不一致状态。

**修复方案**：
```python
def add_message(self, session_id, role, content):
    db = SessionLocal()
    try:
        msg = MessageModel(...)
        db.add(msg)
        db.commit()
    except Exception:
        db.rollback()
        raise
    finally:
        db.close()
```

### 🔵 问题 R-6：frontend/index.html 中 `session_id` 硬编码

| 项目 | 内容 |
|------|------|
| **严重程度** | 🔵 建议 |
| **问题类型** | 会话隔离 |
| **所在文件** | [frontend/index.html](file:///d:/Desktop/MISS/miss-backend/frontend/index.html#L87) |

**问题描述**：
```javascript
body: JSON.stringify({ session_id: 'default', message, profile })
```

所有用户共享同一个 `session_id: 'default'`，不同用户/不同浏览器标签页的对话会混在一起。

**修复方案**：
```javascript
const session_id = localStorage.getItem('miss_session_id') || crypto.randomUUID();
localStorage.setItem('miss_session_id', session_id);
```
