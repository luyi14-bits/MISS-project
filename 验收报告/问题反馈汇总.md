### 🟡 问题 0.1-1：models 中重复定义 Base ✅ 已修复

- **严重程度**：轻微（低）
- **问题类型**：架构设计 / 代码质量
- **修复状态**：✅ 已修复（2026-06-25）
- **所在文件**：
  - [models/session.py](file:///d:/Desktop/MISS/miss-backend/models/session.py)
  - [models/message.py](file:///d:/Desktop/MISS/miss-backend/models/message.py)
  - [models/memory.py](file:///d:/Desktop/MISS/miss-backend/models/memory.py)
  - [models/__init__.py](file:///d:/Desktop/MISS/miss-backend/models/__init__.py)

**问题描述**：
三个模型文件各自独立定义了 `Base = declarative_base()`，这意味着它们属于三个不同的 Base 实例。后续使用 `Base.metadata.create_all(engine)` 创建表时，将无法一次性创建所有表，必须分别调用各自的 Base，这会带来维护困难和潜在 bug。

**修复方案**：
在 `models/__init__.py` 中统一定义 Base，各模型文件从 `__init__` 导入。

```python
# models/__init__.py
from sqlalchemy.orm import declarative_base

Base = declarative_base()

from .session import Session
from .message import Message
from .memory import MemoryEntry
```

```python
# 各模型文件中
from models import Base

class Session(Base):
    ...
```

**修复验证**：
- 模块导入测试通过
- 服务启动正常，/health 端点返回 200

### 🔴 新问题 PACKAGE-2：PyInstaller `excludes=['numpy']` 导致 chromadb 运行时崩溃

- **严重程度**：🔴 严重（阻止打包程序运行）
- **问题类型**：打包配置排除错误
- **状态**：✅ 已修复
- **所在文件**：[build/miss-server.spec L32](file:///d:/Desktop/MISS/miss-desktop-wpf/build/miss-server.spec#L32)
- **影响范围**：`miss-server.exe` 双击后无法启动，traceback 显示 `ModuleNotFoundError: No module named 'numpy'`

**问题描述**：

`miss-server.spec` 中 `excludes` 列表包含了 `'numpy'`，而 chromadb 硬依赖 numpy（`chromadb/api/types.py` 第 20 行 `import numpy`）。PyInstaller 打包时主动排除了 numpy 的字节码，导致运行时导入 chromadb → 导入 numpy 失败 → 整个 FastAPI 后端无法启动。

**影响链路**：

```
双击 MISS.exe
  → C# spawn miss-server.exe
    → main.py → routers/__init__.py → routers/chat.py
      → services/__init__.py → services/vector_store.py
        → chromadb/__init__.py → chromadb/api/types.py
          → import numpy
            ❌ ModuleNotFoundError
              → uvicorn 启动失败
                → WPF 前端 30 秒超时
                  → MessageBox("后端服务启动超时")
```

**修复**：从 `excludes` 列表中移除 `'numpy'`。

```diff
- excludes=['tkinter', 'matplotlib', 'numpy', 'pandas', 'PIL', 'cv2', ...]
+ excludes=['tkinter', 'matplotlib', 'pandas', 'PIL', 'cv2', ...]
```

**修复验证**：PyInstaller 重新打包后，`miss-server.exe` 可在无 Python 环境的机器上独立启动。

**教训**：排除任何包之前必须确认 **所有间接依赖链** 都不需要它。chromadb → numpy 的依赖链不容易直接从代码回溯发现，需要运行时才能暴露。

### 🔴 新问题 PACKAGE-3：PyInstaller 缺少 chromadb 全部子模块 ✅ 已修复

- **严重程度**：🔴 严重
- **问题类型**：打包配置缺失
- **状态**：✅ 已修复（2026-06-26）
- **所在文件**：[build/miss-server.spec](file:///d:/Desktop/MISS/miss-desktop-wpf/build/miss-server.spec)

**验证数据**：

```
PyInstaller collect_submodules('chromadb') → 129 个子模块

当前 spec: 仅 'chromadb' 一个 hidden import
缺失子模块: chromadb.telemetry.product.posthog     ← 本次报错
           chromadb.telemetry.product.events       ← 后续必然报错
           chromadb.telemetry.opentelemetry.*      ← 后续必然报错
           chromadb.db.impl.sqlite                  ← 后续可能报错
           chromadb.segment.impl.manager.local      ← 后续可能报错
           ... 共 128 个
```

```
miss-server.exe → import chromadb
  → chromadb/api/shared_system_client.py L36
    → chromadb/config.py L492 → import_module(...)
      → ❌ ModuleNotFoundError: chromadb.telemetry.product.posthog
        → uvicorn 无法启动
          → WPF 30秒超时 → "后端服务启动超时"
```

**修复方案**：添加 `collect_all('chromadb')` 并过滤 `embedding_functions/`、`test/`、`server/` 等无用 data files。

### SEC-002 假修复详细分析

[LiteDbLocalStore.cs L206-214](file:///d:/Desktop/MISS/miss-desktop-wpf/Services/LiteDbLocalStore.cs#L206-L214)：
```csharp
// LoadSettings() 中尝试从 Python 恢复 key
try {
    var rt = PythonBridge.GetSettings();  // ← RunOnPythonThread 内部检查 _initialized
    ...
} catch { /* bridge not initialized yet */ }
```

`GetSettings()` → `RunOnPythonThread()` → 检查 `_initialized` → **此时 `_initialized` 仍为 `false`**（MarkInitialized 在 Initialize 之后才调用）→ 抛 `InvalidOperationException` → catch 吞掉 → API key = null。

**时序**：
```
App.OnStartup
  Task.Run {
    _engine.Initialize()        // ① 调用 PythonBridge.MarkInitialized() 在此内部
    LocalStore.LoadSettings()   // ② ← 这里调 PythonBridge.GetSettings()
    PythonBridge.ApplySettings()// ③
  }
```

`_engine.Initialize()` 内部（[PythonEngineService.cs L98](file:///d:/Desktop/MISS/miss-desktop-wpf/Services/PythonEngineService.cs#L98)）调用 `PythonBridge.MarkInitialized()` → `_initialized = true`。所以 `LoadSettings()` 在 `Initialize()` **之后**运行是可以拿到 key 的。

**但是**：`GetSettings()` 在 worker thread 上执行 Q → 如果 worker 还没处理到这条 Action，`tcs.Task.Result` 会阻塞。如果之前 `ApplySettings` 在初始化阶段还没有把 key 推到 Python runtime，那 `GetSettings` 返回的 dict 中就没有 `openai_api_key`。

实测验证：Publish 版启动后重启，API Key 仍为空 → `LoadSettings` 中的恢复逻辑从未成功执行。

**第四轮方案**：前三轮尝试的 `BeginInvoke` / `ContentRendered` 均在 self-contained publish 下不触发。本轮改为 `async void OnStartup` + `await Task.Run`——利用 C# 的 `SynchronizationContext` 回调机制，完全不依赖任何 WPF 渲染事件。

实测清单（已 publish 验证）：
- [x] `dotnet publish --self-contained` → MISS.exe ✅
- [x] 双击 2s 内出窗口（Disabled + "正在初始化…" Title） ✅
- [x] Python 引擎初始化完成 (`miss.log: Initialize complete`) ✅
- [ ] `await Task.Run` 完成 → 窗口自动启用 **❌ 实测 40s timeout，Title 永不变**

**根因分析**：`async void OnStartup` + `await Task.Run` 依赖 `SynchronizationContext.Post` 将 `Task.Run` 完成后的 continuation 投递回 UI 线程。但在 self-contained publish (.NET 8 NativeAOT trim) 模式下，`DispatcherSynchronizationContext.Post` 的实现中 `DispatcherOperation` 被 trim 优化，导致 continuation 永久滞留在队列中，Dispatcher 永不抽水。

**建议第五轮方案**：`Dispatcher.Invoke`(同步阻塞) + `Task.Run` fire-and-forget，避免 `SynchronizationContext` 回环依赖。
