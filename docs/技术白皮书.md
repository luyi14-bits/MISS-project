## 1. 产品定位

MISS（Malleable Intelligent Synthetic Soul）是一个 **WPF 桌面 AI 伴侣应用**。核心设计理念：**用户不是在"选择"一个预制角色模板，而是在从零开始"创造"一个人格。**

### 1.1 与传统 AI 伴侣产品的差异

| 维度 | 传统产品（星野/猫箱/Character.AI） | MISS |
|------|-----------------------------------|------|
| 角色起点 | 预制模板（傲娇/温柔/高冷） | **零基线**：10 个维度全部从 0 开始，双向可调 |
| 内心活动 | 无。角色"想什么"和"说什么"是同一套逻辑 | **双轨引擎**：Track A 真实想法 ≠ Track B 说出口的话 |
| 知识边界 | 无论人设，底层全知模型照常回答一切 | **知识天花板**：笨蛋真的不懂量子力学，不是装的 |
| 性格深度 | 语气标签叠加 | **10 维属性 + 交叉影响矩阵**：独立度 + 亲密度 = 傲娇式推拉，不是"贴了标签所以傲娇" |
| 彩蛋机制 | 无 | 文化水平拉至 -100 触发 **⑨模式**：名字变 MISS⑨，口癖 BAKA~，全界面冰蓝色调 |

### 1.2 10 维属性面板

| 属性 | -100 端 | +100 端 | 特殊机制 |
|------|---------|---------|----------|
| **理智—情绪** | 纯理性机器 | 纯情绪驱动 | 两端都无法进行正常恋爱互动 |
| **意志力** | 毫无主见，易被 PUA | 钢铁意志，死不认错 | 过低时理智属性被部分覆盖 |
| **独立—顺从** | 拒绝一切帮助 | 所有决定需用户拍板 | 与亲密度交叉产生傲娇/粘人 |
| **文化水平** | ⑨级笨蛋 | 博学通才 | **拉至 -100 触发⑨彩蛋** |
| **亲密度** | 0（陌生人） | 100（灵魂伴侣） | 全属性"情绪放大器" |
| **好奇心** | 对世界毫无兴趣 | 无止境追问 | 与低文化组合→好奇笨蛋 |
| **幽默感** | 严肃到窒息 | 没正经 | 与攻击性交叉→毒舌/自嘲 |
| **攻击性** | 绝对和平主义 | 火药桶 | 与高意志组合→战姬型 |
| **社交能量** | 深度社恐 | 社交永动机 | 与独立度交叉→孤高/纠结 |
| **冒险精神** | 安全至上 | 极限追逐者 | 与低意志组合→危险莽撞 |

### 1.3 属性交叉影响（5 组精选组合）

10 个属性两两组合有 45 种可能，但只有能产生"可命名、可感知的角色弧线"的组合才被纳入：

| 组合 | 效果 |
|------|------|
| 文化 -100 + 好奇 +100 | **好奇笨蛋**：十万个为什么但每个答案都听不懂 |
| 独立 -100 + 亲密 +100 | **傲娇恋人**："我喜欢你但我不能依赖你" |
| 独立 +100 + 亲密 +100 | **粘人精**：用户是她世界的全部重心 |
| 攻击 +100 + 幽默 +100 | **毒舌喜剧人**：每句话都气人但每句话都好笑 |
| 意志 -100 + 亲密 +100 | **玻璃心恋人**：一句话让她自我怀疑一整天 |

│  ┌─────────┐     pythonnet      ┌─────────┐ │
│  │  C# WPF │ ◄──────────────► │ Python  │ │
│  │ (UI 层)  │   进程内调用       │ (引擎层) │ │
│  │         │                   │         │ │
│  │ .NET 8  │                   │ CPython │ │
│  │         │                   │  3.12   │ │

│       │                             │      │

│       ▼                             ▼      │
│  ┌──────────────┐           ┌────────────┐ │

**零端口占用，零 HTTP 开销。** C# 直接通过 `Python.Runtime` (pythonnet) 嵌入 CPython 3.12 运行时，所有调用是函数级同步，无网络序列化开销。

### 3.3 PythonBridge — 进程内 Python 桥接（232 行）

```
调用方 (UI 线程)                          Python 工作线程 (STA)
┌──────────────────┐           ┌──────────────────────────────┐
│ PythonBridge.    │ 投递到    │ while (true) {               │
│   Chat(...)      │─────────►│   _workQueue.Take()          │
│                  │          │   using (Py.GIL()) {         │
│   TaskCompletion │ 阻塞等待  │     action()  // 执行 Python │
│     Source       │◄─────────│   }                          │
│     .Task.Result │ 返回结果  │ }                            │
└──────────────────┘           └──────────────────────────────┘
```

**设计决策**：
- 单 STA 线程处理所有 Python 调用 → **单线程序列化是 pythonnet 的最佳 GIL 模式**，从根本上消除死锁
- `TaskCompletionSource` 桥接异步等待，调用方用 `Task.Run()` 包裹不阻塞 UI
- `MarkInitialized()` / `MarkDisposed()` 守卫防止未初始化调用

**API 面：**

| 方法 | 功能 |
|------|------|
| `Chat(sessionId, text, profile, background)` | 同步 LLM 对话 |
| `ChatStream(sessionId, text, profile, background)` | 流式对话（yield token） |
| `AnalyzeCharacter(description)` | LLM 分析角色描述 → 返回 10 维属性 |
| `ApplySettings(SettingsData)` | 推送 API 配置到 Python 运行时 |

### 4.2 LLMCaller — 三级 API 降级引擎（312 行）

```
call(messages, model_config)
  │
  ├── Level 1: instructor.apatch(client, Mode.TOOLS/JSON)
  │   ├── 推理模型 (deepseek-reasoner/o1/o3/v4) → Mode.JSON
  │   └── 普通模型 → Mode.TOOLS
  │   ├── 60s 超时, 2 次重试
  │   ├── 成功 → logger.info("[LLM] call complete: level=1, time=Xms")
  │   └── 失败 → logger.warning("[LLM] Level 1 failed → Level 2")
  │
  ├── Level 2: 裸 AsyncOpenAI + response_format={"type":"json_object"}
  │   ├── 独立 AsyncOpenAI 实例（不污染 Level 1 客户端）
  │   ├── response.choices[0].message.content → json.loads
  │   ├── 成功 → logger.info("[LLM] call complete: level=2, time=Xms")
  │   └── 失败 → logger.warning("[LLM] Level 2 failed → Level 3")
  │
  └── Level 3: 裸 AsyncOpenAI + prompt 约束
      ├── system prompt 注入 JSON 输出格式指令
      ├── response.choices[0].message.content[:10000] → json.loads
      ├── 成功 → logger.info("[LLM] call complete: level=3, time=Xms")
      └── 失败 → 安全占位符 "响应格式异常，请检查 API 配置"
                 (不原文透传，防止 system prompt 泄漏)
```

**推理模型检测表：**

| 模型关键词 | Mode | Level 1 行为 |
|-----------|------|-------------|
| `reasoner` (deepseek-reasoner) | JSON | 不使用 tool_choice |
| `o1-mini`, `o1-preview`, `o3-mini` | JSON | OpenAI 推理模型不兼容 TOOLS |
| `v4-pro`, `v4-flash` | JSON | 第三方推理模型 |
| `gpt-4o`, `gpt-4o-mini`, `deepseek-chat` 等 | TOOLS | function calling 完整支持 |

**流式模式（stream()）**：
- Level 1 (instructor stream) → 失败自动降级
- Level 2 (裸 AsyncOpenAI + stream=True) → 同样 `_parse_json_response` 二次校验
- `_parse_json_response` 对 JSON 解析失败的原始 LLM 输出**完全丢弃** → 返回安全占位符（阻止注入/泄漏）

| `MISSProfile` | Pydantic 基类（10 维 + Field ge/le + allowed_domains + description） |
| `EasterEggEngine` | 文化水平=-100 → 返回 cirno_mode 配置字典（名前缀⑨、口癖 BAKA~、图标冰翼等） |
| `CrossEffectCalculator` | 10 组精确匹配规则 → 返回激活的交叉人格列表（如 curious_baka, tsundere_lover） |
| `AttributePromptMapper` | 每个属性 7 级分层（-100/-67/-33/0/33/67/100）→ 映射为 XML 描述片段 |
| `KnowledgeFilter` | 后端二次校验。低教育水平时检测 50+ 专业术语 → 替换/降级为日常表达 |
| `IntimacyEngine` | 基于对话的语义分析评估亲密度变化量 |

### 4.5 提示词系统（prompt_builder.py + miss_system.j2）

**Jinja2 模板 8 大区块：**

| 区块 | 内容 | 对应引擎 |
|------|------|----------|
| `<system_directive>` | 核心身份声明 | — |
| `<persona>` | 角色名 + ⑨模式口癖注入 | `EasterEggEngine` |
| `<dynamic_state>` | 10 维属性 XML 描述块 | `AttributePromptMapper` |
| `<knowledge_ceiling>` | 知识天花板（4 级分支） | `KnowledgeFilter` 规则 |
| `<easter_egg>` | ⑨模式完整配置 | `EasterEggEngine` |
| `<cross_persona>` | 激活的交叉人格 | `CrossEffectCalculator` |
| `<cognitive_engine>` | Track A（内心独白）+ Track B（说出的话）决策树 + 情绪策略矩阵 | — |
| `<behavioral_constraints>` | 10 条反面目标（禁止行为清单） | — |
| `<recalled_memories>` | 语义检索历史记忆 | `VectorMemoryStore` |
| `<response_format>` | JSON 输出模板 | — |

**双轨引擎在提示词层**：Track A（内心独白，用户不可见）+ Track B（社会化表达，用户可见）。双轨不拆为独立 Python 模块——提示词表达能力远超代码层。

### 4.6 记忆系统

```
工作窗口 (最近20轮)
  └─ ConversationStore.get_window() → SQLite messages 表

长期记忆 (无上限)
  └─ MemoryScorer.score()              # 纯本地规则：长度+关键词+角色+情感密度
      └─ MemorySummarizer.process()
          ├─ ≥80 → 保留原文 → SQLite + ChromaDB
          ├─ 40-79 → 标点截断(≤50字) → SQLite + ChromaDB
          └─ <40 → 丢弃

语义检索
  └─ VectorMemoryStore.recall(query, top_k=5)
      └─ ChromaDB PersistentClient (默认模型: all-MiniLM-L6-v2)
```

## 5. AI 引擎

### 5.1 支持的 API 提供商

| 提供商 | 模式 | Level |
|--------|------|-------|
| **OpenAI** (GPT-4o, GPT-4o-mini) | TOOLS → JSON → 裸API | 1→2→3 |
| **DeepSeek** (deepseek-chat) | TOOLS → JSON → 裸API | 1→2→3 |
| **DeepSeek** (deepseek-reasoner) | **跳过 TOOLS** → JSON → 裸API | 2→3 |
| **OpenAI** (o1-mini, o3-mini) | **跳过 TOOLS** → JSON → 裸API | 2→3 |
| **中转站/兼容 API** | JSON → 裸API | 2→3 |
| **任意 OpenAI 兼容 API** | 裸API (prompt 约束) | 3 |

### 5.2 三种 Level 的工作原理

**Level 1 (instructor Mode.TOOLS)**：
- 底层发送 `tool_choice` 参数，OpenAI 模型直接返回 JSON
- 最强约束，最高可靠性
- 仅 OpenAI 官方/兼容 API 有效

**Level 2 (response_format)**：
- 裸 `AsyncOpenAI` + `response_format={"type":"json_object"}`
- 大多数 OpenAI 兼容 API 支持
- 兜底：手动 `json.loads` 解析

**Level 3 (裸 API + prompt 约束)**：
- 无 tool_choice、无 response_format
- 仅靠 prompt engineering 引导模型输出 JSON
- 全网最低兼容需求

### 6.1 安全基线

| 维度 | 状态 |

### 6.2 关键安全机制

| 层 | 机制 | 实现 |
|----|------|------|
| **认证** | Bearer Token 中间件 | `access_token` 空时不校验（本地桌面免配置） |
| **传输** | 进程内 pythonnet 调用 | 零网络暴露，C# ↔ Python 函数级调用 |
| **加密存储** | Fernet AES-128-CBC | 消息 Text/InnerThought 加密后存 LiteDB |
| **API Key 保护** | 加密后落盘 | LiteDB 序列化前加密 `openai_api_key`，内存中恢复 |
| **崩溃防御** | `DispatcherUnhandledException` | 所有未处理异常弹出对话框 + 写入 `crash.log` |
| **SSE 错误** | `JsonSerializer.Serialize` | 动态序列化替代硬编码字符串拼接 |
| **异常保护** | `except Exception: pass` 全部消除 | 27 处异常路径均有 logging.warning |
| **LLM 输出净化** | JSON 解析失败 → 安全占位符 | 绝不原文透传（防 system prompt 泄漏） |
| **_error 格式** | 统一 `{"_error": True, "message": str}` | C# 侧单一布尔检测，无遗漏 |
| **速率限制** | slowapi Limiter | `POST /chat`: 10/min, `POST /character/analyze`: 5/min |

### 6.3 安全数据流

```
用户输入
  │
  ├── BridgeProfile ge/le 强校验                    ← 输入层
  │
  ├── 进程内 pythonnet 函数调用（零网络）              ← 传输层
  │
  ├── instructor + pydantic 约束 LLM 输出             ← 应用层
  │   └── json.loads 失败 → 安全占位符（不原文透传）
  │
  ├── Fernet 加密 → LiteDB BSON                      ← 持久层
  │
  └── API Key: 仅内存持有，落盘前加密                  ← 配置层
```

### 6.4 异常处理完整性

全项目 **0 处 `except Exception: pass`**（无日志的静默吞异常）：

- `services/` 全部 11 处 `except Exception` 均有 `logging.warning/error` 或 `db.rollback() + raise`
- `llm_caller.py` 三条异常路径（Level 3 timeout/RuntimeError/generic）均有日志
- `desktop_bridge.py` 所有异常透传为 `{"_error": True, "message": str}`
- 唯一 `pass` 位于 `desktop_bridge.py:pysqlite3` 可选导入降级——已有注释说明
